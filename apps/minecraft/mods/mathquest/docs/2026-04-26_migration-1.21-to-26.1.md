# Migrating MathQuest from 1.21.11 (Yarn) to 26.1.2 (Mojang mappings)

Minecraft 1.21.11 was the last version Mojang shipped obfuscated. Starting with the new
26.1 release line (year.drop.hotfix versioning), the game ships with real class /
method / field / parameter names. As a consequence:

- Yarn and Intermediary are no longer published past 1.21.11.
- Loom switched to a new plugin id (`net.fabricmc.fabric-loom`) that does no remapping.
- Mods on Yarn need a one-time source migration to Mojang names before they can target
  26.1.x.

That migration has now been completed. `fabric-1.21.11` builds from Mojang-named source
with official mappings, and `fabric-26.1.2` builds with the new no-remap Loom plugin.

## Completed outcome

- `fabric/src/main/java/` is Mojang-named and remains the shared source of truth for the
  code that is source-compatible across both Fabric targets.
- `targets/fabric-1.21.11` uses `loom.officialMojangMappings()` and Loom 1.14 on the
  Gradle 9.4.1 wrapper.
- `targets/fabric-26.1.2` uses `net.fabricmc.fabric-loom`, no explicit `mappings`
  dependency, Fabric Loader 0.18.5, Fabric API 0.146.1+26.1.2, and Java 25.
- A small `targets/fabric-26.1.2/src/main/java/` override set handles source-incompatible
  26.1 API names: `ClientCommands`, `PayloadTypeRegistry.serverboundPlay/clientboundPlay`,
  `GuiGraphicsExtractor`/`extractRenderState`, and mob interaction/message methods.
- `./gradlew buildAll` builds both Fabric targets by default.

## 2026-04-27 playtest

Randy manually smoke-tested both built jars in Minecraft. For each version, he launched
the game, ran `/mathquest start` to manually trigger The Wandering Nerd flow, accepted
the quiz, answered all five questions, and closed the quiz UI. This passed on both
`fabric-1.21.11` and `fabric-26.1.2`.

## What changes in your source

Yarn names and Mojang names overlap surprisingly little for client-facing classes:

| Yarn (current source)              | Mojang (post-migration)                  |
|------------------------------------|------------------------------------------|
| `net.minecraft.client.MinecraftClient` | `net.minecraft.client.Minecraft`         |
| `net.minecraft.util.Identifier`        | `net.minecraft.resources.ResourceLocation` |
| `net.minecraft.text.Text`              | `net.minecraft.network.chat.Component`   |
| `net.minecraft.entity.player.PlayerEntity` | `net.minecraft.world.entity.player.Player` |
| `net.minecraft.item.ItemStack`         | `net.minecraft.world.item.ItemStack`     |
| `net.minecraft.client.gui.screen.Screen` | `net.minecraft.client.gui.screens.Screen` |

Method names also shift — `getInventory()` ↔ `getInventory()`, `getStackInHand()` ↔
`getItemInHand()`, etc. There are hundreds of these. You don't translate by hand; Loom
does it.

## Step-by-step

You need a machine with internet access (to fetch Loom + the requested mappings).
Everything below runs from `mathquest/`.

### 1. Generate Mojang-named source

Run Loom's `migrateMappings` task on the 1.21.11 target, telling it to target the
official mappings of the same MC version:

```bash
./gradlew :targets:fabric-1.21.11:migrateMappings \
    --input "/absolute/path/to/mathquest/fabric/src/main/java" \
    --output "/absolute/path/to/mathquest/targets/fabric-1.21.11/remappedSrc" \
    --mappings "net.minecraft:mappings:1.21.11"
```

In this multi-project layout, pass absolute `--input` / `--output` paths; without them
Loom can report `NO-SOURCE` because the target consumes shared source outside its own
project directory. Loom writes the rewritten source to `targets/fabric-1.21.11/remappedSrc/`.
**It does not modify the original source.**

### 2. Verify it compiles

Temporarily point the 1.21.11 target at the migrated source:

- Edit `targets/fabric-1.21.11/build.gradle`.
- In the `dependencies` block, replace
  `mappings "net.fabricmc:yarn:${project.yarn_mappings}:v2"` with
  `mappings loom.officialMojangMappings()`.
- In the `sourceSets.main.java.srcDirs = [...]` list, replace the
  `rootProject.file('fabric/src/main/java'),` entry with `'remappedSrc',`
  (just for this verification step). The list right now looks like:

  ```groovy
  java {
      srcDirs = [
          rootProject.file('fabric/src/main/java'),       // ← change this line
          rootProject.file('common/src/main/java'),
      ]
  }
  ```

- Run `./gradlew :targets:fabric-1.21.11:compileJava` and chase down any compile
  errors. Most failures are Mixin targets or reflection strings that the migrator
  couldn't see.

### 3. Promote the migrated source

Once it compiles:

```bash
rm -rf fabric/src/main/java
mv targets/fabric-1.21.11/remappedSrc fabric/src/main/java
```

Revert the temporary `'remappedSrc'` change you made to `srcDirs` in step 2 — restore
`rootProject.file('fabric/src/main/java')`. The 1.21.11 target now reads from the
shared `fabric/src/` again, but the contents are in Mojang names.

### 4. Update the 1.21.11 target permanently

Keep `mappings loom.officialMojangMappings()` (don't switch back to Yarn). Drop the
`yarn_mappings` line from `targets/fabric-1.21.11/gradle.properties` — it's unused now.

The 1.21.11 target still builds and still ships a working 1.21.11 jar. It just speaks
Mojang names internally.

### 5. Bring fabric-26.1.2 online

The 26.1.2 target initially shipped with a placeholder `src/main/java/.gitkeep`. During
the actual port, a few APIs proved source-incompatible with 1.21.11, so this directory is
now used for a small override set rather than a full parallel source tree.

`targets/fabric-26.1.2/build.gradle` syncs shared source into
`build/generated/shared-main`, excluding the overridden classes, then compiles:

```groovy
java {
    srcDirs = [
        layout.buildDirectory.dir('generated/shared-main').get().asFile,
        rootProject.file('common/src/main/java'),
        'src/main/java',
    ]
}
```

The new Loom plugin is a no-remap plugin for unobfuscated Minecraft, so do **not** add a
`mappings loom.officialMojangMappings()` dependency to `fabric-26.1.2`; it fails with
`Cannot use Mojang mappings in a non-obfuscated environment`.

The target is now in `DEFAULT_TARGETS`, so this builds both targets:

```bash
./gradlew buildAll
```

Expect compile errors against 26.1-specific Fabric API renames. The official
[Fabric API 26.1 porting guide](https://docs.fabricmc.net/develop/porting/fabric-api)
lists every rename. Most edits are mechanical (e.g. `FabricLoader.getInstance()` is
unchanged; some event hook names moved package).

### 6. Bump Java toolchain for 26.1

26.1.x needs Java 25. In `targets/fabric-26.1.2/build.gradle`, override the inherited
toolchain:

```groovy
java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(25)
    }
}

tasks.withType(JavaCompile).configureEach {
    options.release = 25
}
```

Leave the 1.21.11 target on Java 21.

### 7. Bump the Gradle wrapper

Loom 1.15 requires Gradle 9.4+. The wrapper was bumped to Gradle 9.4.1:

```bash
./gradlew wrapper --gradle-version 9.4.1
```

The 1.21.11 target was bumped to `loom_version=1.14` in
`targets/fabric-1.21.11/gradle.properties`. Loom 1.13.x refuses to run on Gradle 9.

## Things that DON'T change

- The shared `fabric/src/main/resources/` (lang files, generated textures) — Mojang
  mappings don't affect resources.
- The platform-agnostic code that will eventually live in `common/src/` — pure Java,
  no Minecraft imports, no migration needed.
- Test code under `fabric/src/test/` if it doesn't import from `net.minecraft`.
  `QuizManagerTest.java` and `ConfigTest.java` are likely safe; the others may need
  spot updates.

## If something goes badly wrong

The migration is reversible until step 3. If you decide to back out:

```bash
rm -rf targets/fabric-1.21.11/remappedSrc
git checkout -- targets/fabric-1.21.11/build.gradle
```

The shared `fabric/src/` was untouched, so the 1.21.11 target still builds the way it
always did.
