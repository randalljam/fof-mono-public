**MathQuest problem sources and Math Quiz session integration**

## Purpose
This document is the current starting point for expanding MathQuest from a simple
quiz/reward loop into a richer game system where story, world mechanics, rewards,
and math fluency progression can all use the same learner data.

It records what is implemented now:

- How MathQuest chooses quiz problems.
- How Minecraft player names map to real learner names.
- How completed MathQuest sessions are written as single-session SQLite files.
- How those single-session files are appended into the active multi-session Math
  Quiz learner files.
- Which parts are ready to build story or progression mechanics on top of, and
  which parts are still deliberately outside this document.

The companion schema reference is
`apps/minecraft/mods/mathquest/docs/SQLITE_SCHEMA_REFERENCE.md`.

## Current implementation summary
MathQuest currently has four standard-arithmetic problem sources and one separate
written-column quiz type.

| Source | Config value | Where problems come from | Control-panel behavior | Completion behavior |
| --- | --- | --- | --- | --- |
| Internal quick quiz | `internal_quick_quiz` | `QuickPracticeItems` rows in the learner's latest Math Quiz SQLite file | Default source. Operation remains editable. Range and problem count stay visible but disabled. | Exports a MathQuest single-session SQLite file and appends it into the learner's active Math Quiz file. Quick-quiz rows are not consumed. |
| Internal problem list | `internal_problem_list` | First queued `ProblemLists` row and ordered `ProblemListItems` rows in the learner's latest Math Quiz SQLite file | Operation, range, and problem count stay visible but disabled because the list supplies exact problems. | Exports and appends like any standard arithmetic quiz, then either retains or deletes the used problem list according to its `retain` value. |
| Internal fluency feast | `internal_fluency_feast` | Generated at quiz-open time from the learner's `ProblemAttempts` history plus per-file `FluencyFeastConfig` and `Profile` rubric (same parameters as math-quiz Fluency feast / generate-by-fluency) via the bundled Node bridge running `fluency_core.js` | Operation, range, and problem count are disabled; feast parameters are edited in the math-quiz analysis/anchor page and stored in the learner `.sqlite`. | Exports and appends like any standard arithmetic quiz. Shows `Fluent: A% -> B%` on the result screen; grants the dedicated fluency-improvement reward when `% fluent` rises by at least one point (replacing the normal reward). Requires `node` on the server/laptop. |
| Generated arithmetic | `generated` | MathQuest config operation, operand range, and problem count | Operation, range, and problem count are editable. | Exports and appends like any standard arithmetic quiz. |
| Written column arithmetic | `written_column_arithmetic` quiz type | One paper-style prompt generated by MathQuest and evaluated by an adult with the evaluator code | Separate quiz type, not one of the standard arithmetic source modes. | Writes a separate written-column SQLite file. It is not appended into the standard Math Quiz multi-session file. |

The default standard-arithmetic source for the configured family players is
`internal_quick_quiz`.

## Player identity
MathQuest distinguishes Minecraft player names from real learner names.

The current built-in/default mapping is:

| Minecraft player | Real name |
| --- | --- |
| `rjcomp` | `Randy` |
| `TreasureHunterM` | `K2` |
| `PumaJockey` | `TL` |
| `SkulkScraper` | `Guest` |
| `WildPetal` | `Kid1` |

Runtime edits from the MathQuest control panel are stored in `mathquest.json` in
`playerRealNames`; those override the built-in defaults.

The real name is used for:

- Finding the learner's Math Quiz SQLite file in `_data/tlkids`.
- Reading internal quick-quiz rows and queued problem lists.
- Naming MathQuest single-session SQLite exports.
- The `Users.name` and `Sessions.user_name` values inside exported standard
  arithmetic SQLite files.

## Source selection flow
### Dedicated server / multiplayer
In server mode, the server is authoritative for problem source selection.

1. A player interacts with a MathQuest NPC.
2. The server resolves the player's config:
   - real name
   - quiz type
   - standard arithmetic source
   - operation/range/problem-count settings
   - reward plan
3. `QuizPayloadBuilder` builds an `OpenQuizPayload`.
4. If the source is `internal_problem_list`, the server tries to load the first
   queued problem list for the real name.
5. If the source is `internal_quick_quiz`, the server tries to load quick-practice
   rows for the selected operation.
6. If no usable internal source is found, MathQuest falls back to generated
   arithmetic using the configured operation/range/problem count.
7. The client receives the payload, opens the quiz UI, and sends the completed
   result back to the server with `QuizResultPayload`.
8. The server writes local MathQuest result data, exports a Math Quiz-compatible
   single-session SQLite file, and runs the ingest bridge to append that file into
   the active learner file.

Child/player machines do not need local copies of the Math Quiz SQLite files in
server mode. The server reads and writes the local files on Randy's laptop/server.

### Singleplayer
In singleplayer, the local client resolves the same source modes from its local
MathQuest config.

The same standard arithmetic export and ingest path is called after the quiz is
completed. Singleplayer therefore also writes:

- a raw single-session SQLite file in `mathQuizExportDir`
- an appended session in the active file under `mathQuizActiveDir`

The local Prism instance config may omit `mathQuizActiveDir`; in that case the
current default `_data/tlkids` is used.

## Internal quick quiz
Internal quick quiz is the current default problem source.

It reads from the learner's latest Math Quiz SQLite file in `_data/tlkids`. The
file lookup uses the real learner name and `math-flu` file naming. The loader
chooses the most recently modified matching file for the real name.

Required table:

- `QuickPracticeItems`

Rows are filtered by:

- `user_name = <real name>`
- `operation = <symbol>`

Supported operations for this source:

| MathQuest operation | SQLite operation symbol |
| --- | --- |
| addition | `+` |
| subtraction | `-` |
| multiplication | `*` |

The source currently expects a small ordered list; the working convention is seven
quick-practice problems per operation. MathQuest sends those problems to the quiz
screen in order.

Quick-quiz rows are not consumed by MathQuest. The Math Quiz side is responsible
for regenerating or editing them as the learner's data changes.

## Internal problem list
Internal problem list is the queued, coach-authored source.

It reads from:

- `ProblemLists`
- `ProblemListItems`

Selection rule:

1. Find the learner's latest `math-flu_<real-name>_*.sqlite` file in `_data/tlkids`.
2. Select the first `ProblemLists` row for that user ordered by
   `list_order, problem_list_id`.
3. Load that list's `ProblemListItems` ordered by
   `item_order, problem_list_item_id`.

When a quiz using an internal problem list completes, MathQuest calls the consume
logic:

- If `retain = 1`, the list stays in place and `times_used` plus `last_used_at`
  are updated.
- If `retain = 0`, the list and its items are deleted, and remaining lists for
  that user are reindexed to contiguous `list_order` values.

The active list is remembered in memory between quiz-open and quiz-completion.
If the server restarts during a quiz, the list may not be consumed even if the
session export succeeds.

## Generated arithmetic
Generated arithmetic is the fallback and manual settings mode.

It uses MathQuest config values:

- `operation`
- `minNumber`
- `maxNumber`
- `problemsPerQuiz`
- optional per-player overrides in `playerPresets`

Supported operations in MathQuest:

| Operation | Problem form |
| --- | --- |
| addition | `factorA + factorB` |
| subtraction | `factorA - factorB` |
| multiplication | `factorA * factorB` |
| division | integer-style division problems as generated by `QuizManager` |
| exponentiation | integer powers; `0^0` is treated as `1` |

Generated sessions export to the same standard arithmetic SQLite schema as
internal-source sessions.

## Standard arithmetic completion flow
When a standard arithmetic quiz completes:

1. MathQuest writes/updates its legacy local `mathquest_data.db`.
2. `SessionExporter` writes a raw single-session SQLite file:
   `mathquest_<real-name>_<YYYY-MM-DD_HHMMSS>.sqlite`.
3. The file lands in `mathQuizExportDir`, normally
   `_data/_single-session-sqlite-files`.
4. `MathQuizSessionIngestor` runs the shared Python ingest helper:
   `session_ingest.py`.
5. The helper archives/copies the raw single-session file if needed.
6. The helper appends the session into `mathQuizActiveDir`, normally
   `_data/tlkids`.
7. The server log reports:
   - the raw single-session SQLite path
   - the ingest helper script path
   - the active multi-session SQLite path updated

The ingest helper is bundled inside the MathQuest jar as of `1.11.10`.
At runtime, if no checkout copy of `session_ingest.py` is found, MathQuest extracts
the bundled `session_ingest.py` and `anchor_store.py` into
`mathquest_ingest_tools/` under `sharedDataDir`.

## Active multi-session append rule
MathQuest invokes `session_ingest.py` with:

- `--prefix mathquest`
- `--match-any-prefix`

That means the raw file can be named with the `mathquest_` prefix while the active
learner file can keep its Math Quiz `math-flu_` prefix.

The active file lookup rule is:

1. Find files in `mathQuizActiveDir` whose filename contains the exact real-name
   segment surrounded by underscores, such as `_Randy_`.
2. Ignore the prefix when matching, so both `math-flu_Randy_...sqlite` and
   `mathquest_Randy_...sqlite` are candidates.
3. Choose the newest filename date after the name.
4. If the target is already a multi-session file, append into it and keep its
   filename.
5. If the target is a single-session file, copy/rename to the corresponding
   multi-session filename and append.
6. If no target exists, create a new `mathquest_<real-name>_<timestamp>.sqlite`
   active file.

For the intended TLKids workflow, the active folder should already contain files
like:

```text
apps/math-quiz/_data/tlkids/math-flu_Randy_2026-06-16.sqlite
```

In that case a completed MathQuest quiz for `rjcomp -> Randy` should append into
that file rather than create a new `mathquest_Randy_...sqlite` file.

## Logs to expect
A successful standard arithmetic server completion should include lines like:

```text
[MathQuest] Math Quiz single-session SQLite written: /.../_data/_single-session-sqlite-files/mathquest_Randy_2026-06-27_101500.sqlite
[MathQuest] Math Quiz session ingest script: /.../mathquest_ingest_tools/session_ingest.py
[MathQuest] Math Quiz multi-session SQLite updated: /.../_data/tlkids/math-flu_Randy_2026-06-16.sqlite (action=append, added=1)
[MathQuest] Server recorded quiz result for rjcomp (2/3 correct)
```

If the updated path says `_data/tl-kids`, the server is using an old config or old
jar. If the action says `create` when a `math-flu_<real-name>_...sqlite` file
exists in `_data/tlkids`, check the real-name mapping and the exact active folder.

## Current extension points for richer game design
These concepts are available now and can be used by future story/world mechanics:

- Player identity is stable through the Minecraft-player to real-name mapping.
- Problem source is per player and configurable.
- Operation/range/problem count are per player for generated arithmetic.
- Internal quick quiz can represent the current practice target from Math Quiz.
- Internal problem lists can represent a coach-authored quest step or explicit
  progression gate.
- `ProblemListItems.category` and `notes` already exist in the SQLite schema and
  are good candidates for carrying future story/category metadata.
- Completed standard arithmetic sessions are appended into the same learner file
  Math Quiz uses for fluency analysis.
- Rewards and NPC selection are already per player in MathQuest config/control
  panel state.

This document intentionally does not define the future story categories, quest
sequence, progression rules, or world mechanics. Those should be designed on top
of the data contracts described here.
