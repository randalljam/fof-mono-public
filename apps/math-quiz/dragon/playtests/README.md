Simulated full-playthrough testing for the dragon fluency game. A seeded **simulated learner** plays the real game loop end to end from a starting SQLite file — every burst generated by the real Fluency Feast code, every session saved through the real dev-server pipeline, fluency recomputed from the file by the real rubric — and the whole run is recorded as an event stream plus a human-readable markdown report.

The apparatus is **purely additive**: no engine, schema, or game-logic changes. The one infrastructure touch is the `ANCHOR_S3_DISABLE=1` env flag in `tools/dev_server.py` so simulated runs never upload to the real S3 bucket.


## The simulated learner
`simulation/dragon_learner.mjs`. The 55 addition facts are grouped into three tiers from the real segmentation categories (`engine/addition_segmentation.mjs`):

| Tier | Categories | Start median RT | Start accuracy |
|---|---|---|---|
| easy | Add 0, Add 1 | 1500 ms | 96% |
| medium | Add 2, Doubles | 3400 ms | 82% |
| hard | Tough 21 | 6200 ms | 62% |

Each exposure to a fact makes the learner **10% faster** on it (configurable) and +5pp more accurate, with floors/ceilings. Because the baselines are staggered around the 2000 ms green threshold, the tiers reach fluency in order easy → medium → hard. All randomness is seeded — runs are deterministic.

## The starting SQLite file
`simulation/dragon_seed.mjs` simulates a 3-session baseline history (~40% fluent: easy green, medium half green/half yellow, Tough 21 red/gray) and writes a real `math-flu_<user>_<date>.sqlite` via the real `createTables`/`importSessionData`. Starting below 60% means a full run crosses every milestone (hatch 60 → wings 70 → jumps 80 → fire 90 → flight-ride 100).

## Two drivers, one loop
1. **Headless** (`simulation/dragon_playthrough.mjs`) — the full game progression loop in Node against a spawned dev server (seconds per run). From the repo root:

```
node apps/math-quiz/simulation/dragon_playthrough.mjs
```

Options: `--run-dir <dir>` `--port 8931` `--user DragonSim` `--folder playtest` `--seed <s>` `--rate 0.10` `--max-bursts 100` `--blank` `--report-out <tracked .md>`. Requires `npm install` in `apps/math-quiz/tests` (sql.js).

2. **Browser** (`tests/e2e_playthrough/dragon_playthrough.spec.mjs`) — plays the REAL game UI in headless Chromium: pointer-lock look/walk, egg discovery, keyboard answers into the quiz overlay, waits through hatch/milestone/flight cutscenes, rides the dragon at 100%, screenshots every beat. ~5-15 min for a full arc. From `apps/math-quiz/tests`:

```
npm run test:playthrough
```

Env knobs: `DRAGON_MAX_BURSTS` (cap for shakeouts), `DRAGON_SEED`, `DRAGON_REPORT_OUT` (also write the tracked report to this path). Deliberately **not** part of `npm run test:e2e`.

Response-time injection (browser): an init script wraps `performance.now()` with a driver-controlled offset, and a second init script shims the Pointer Lock API (headless Chromium grants no real pointer lock). Both are test-context-only — the game code is untouched.

## Data safety
- Runs use learner `DragonSim` in folder `playtest` inside sandbox data dirs (headless: per-run `runs/<stamp>_headless/data`; browser: `runs/browser-server-data`). **Never** `tlkids` / real learner files.
- The dev server is started with `ANCHOR_S3_DISABLE=1` and a sandboxed `ANCHOR_BACKUP_DIR` — nothing reaches S3 or the real backup folder.
- `runs/` is gitignored (sqlite, events.jsonl, screenshots). Only the markdown reports in this folder are tracked.

## Reports
`simulation/playthrough_report.mjs` renders `events.jsonl` into markdown: run parameters, seed start-state per category, burst-by-burst table (fluency %, score, per-tier median RT, categories served, milestone reveals), milestone timeline, category progression, outcome, UX log (browser), and a "Game changes discovered" section. Tracked reports in this folder:
- `2026-07-03_simulated-playthrough.md` — headless full arc
- `2026-07-03_browser-playthrough.md` — real-UI full arc

## Unit tests
`tests/dragon_sim_learner.test.mjs` (model behavior against the real fluency rubric) and `tests/dragon_playthrough_smoke.test.mjs` (capped in-memory loop, no server). Run with the normal unit suite: `node --test apps/math-quiz/tests/*.test.mjs`.
