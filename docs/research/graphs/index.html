Graphs as data structures

A graph is a way to model things and relationships. The same idea can describe friendships, roads, prerequisites, function calls, lesson dependencies, recommendation paths, and causal claims.

The compact definition

A graph has nodes and edges. Nodes are the things. Edges are the relationships between them.

A DAG is a directed acyclic graph: every edge points one way, and following arrows can never bring you back to where you started.

Node / vertex

An entity: a learner, skill, file, function, lesson, task, commit, city, or concept.

Edge / relationship

A connection: depends on, calls, unlocks, follows, influences, resembles, links to, or is adjacent to.

Traversal / query

An algorithmic walk: find neighbors, trace prerequisites, detect loops, rank importance, or choose the next step.

Graphs in edtech and AI education software

Graphs become useful when educational content stops being a flat list. They let software reason about dependency, sequence, similarity, mastery, evidence, and explanation.

How this relates to docs/codeindex

The code-index script is already using graph ideas. It parses Python files with ast, treats user-defined functions as graph nodes, and treats function calls as directed edges.

Concrete mapping:

generate_graph_data() creates graph_nodes with IDs like module.function, then creates graph_edges from caller to callee.

That makes the codebase searchable as a call graph: "what does this function call?" and "what calls this function?"

Useful mental models

Structure

What entities exist, and which relationships are allowed?

Direction

Does the edge mean A relates to B, or specifically A points to B?

Cycles

Can the relationship loop back? Sometimes cycles are natural; sometimes they are an error.

Algorithms

What do you need to compute: path, order, cluster, influence, centrality, or recommendation?

Reference map

DAG

Best for dependencies, prerequisites, build steps, course paths, version histories, and causal models that cannot loop.

Knowledge graph

Best for richly typed entities and relationships: concept relates-to concept, lesson teaches skill, learner shows evidence for standard.

Graph database

A storage/query system optimized for traversing relationships, such as finding nearby concepts or prerequisite chains.
