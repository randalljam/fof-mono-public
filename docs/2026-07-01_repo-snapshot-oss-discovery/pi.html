Deep dive · the third harness on your list

Pi (earendil-works)

The "Pi" you flagged next to Hermes and OpenClaw: an open-source (MIT), TypeScript, minimal terminal coding harness — and an embeddable SDK — by Mario Zechner (of libGDX fame). It bundles a unified multi-provider LLM API, an agent loop, a terminal UI, and a coding CLI as small composable packages. It's deliberately a lego kit, not a batteries-included app: OpenClaw is built on Pi's SDK, which is exactly why it sits in your "harnesses to evaluate" list.

The one-paragraph fit for you

Pi is most valuable to you as an engine, not a daily driver. You're a non-coder operator who's happy on Claude Code (cloud) and Codex (local) — finished harnesses with permission systems and built-in workflow. Pi is the opposite: minimal, unopinionated, and meant to be embedded to build your own agent surface. Its natural home in your world is under a custom tool — think a future rebuild of your Hermes bot, or a bespoke agent your agents assemble — where you want to own the loop. As a hands-on CLI it has one real caution for you: no built-in permission system — it runs with your full user permissions unless you sandbox it yourself.

✅ What's genuinely interesting

  • An embeddable agent runtime (SDK) — the thing OpenClaw builds on.
  • Reads AGENTS.md — your convention, out of the box.
  • Unified API across ~25 providers; MCP supported.
  • Tiny, hackable, fast-moving; four run modes incl. RPC + SDK.

⚠️ Why it's "watch," not "adopt"

  • No permission system — full user perms by default; sandbox is bring-your-own.
  • Minimalist: no built-in subagents/plan-mode — you compose them.
  • Young (created Aug 2025); embedding it is dev work.
  • Finished harnesses serve your daily flow better.
01 · Technical

How it works

A monorepo of small packages (SDK + CLI)

  • @earendil-works/pi-ai — unified multi-provider LLM API (Anthropic, OpenAI, Google, Bedrock, Groq, OpenRouter, and ~20 more).
  • @earendil-works/pi-agent-core — the agent runtime: tool-calling loop + state. This is what OpenClaw embeds via createAgentSession(), rather than shelling out to a CLI.
  • @earendil-works/pi-coding-agent — the interactive coding CLI (pi).
  • @earendil-works/pi-tui — terminal UI with differential rendering.

Runtime model

  • Tiny default toolset: the model gets four tools — read, write, edit, bash. Everything else is added via packages.
  • Four run modes: interactive (TUI), print/JSON (headless), RPC (process integration), and SDK (embed in your app — the OpenClaw path).
  • Extensibility is the whole point: TypeScript Extensions, Skills, Prompt Templates, and Themes, bundled into shareable Pi Packages (npm or git). Sub-agents and plan mode are deliberately not built in — you add them.
  • Context: reads AGENTS.md; supports session branching, compaction, and token/cost accounting; MCP supported.

Isolation — the important caveat

Pi ships no permission system — by default it runs with the full permissions of the launching user, unlike Claude Code's confirmation prompts. Sandboxing is opt-in/bring-your-own; the docs point to Gondolin (a local Linux micro-VM), plain Docker, or OpenShell. Supply-chain hardening (pinned deps, --ignore-scripts, audit in CI) is a stated priority. Local-first: install via npm or the install script; no hosted runtime; bring your own keys/subscription.

The honest placement

Of your three "harnesses to evaluate" (Hermes, OpenClaw, Pi), Pi is the foundation the other one is built on. So the practical question isn't "should I switch to Pi?" — it's "if I ever rebuild Hermes or want a custom agent, should I build it on Pi's SDK?" For that, Pi is a strong, MIT, actively-developed choice with your AGENTS.md convention baked in. As a tool you personally drive day-to-day, it asks more assembly than a non-coder operator wants, and its missing permission system is a real safety gap for unattended use.

03 · Cautions

What to watch

No permission system

Runs with full user permissions by default. For an operator who won't read the code an agent runs, that's the single biggest caution. Handle: only ever run Pi inside a sandbox (Docker/Gondolin) with no production credentials — never bare on your Mac.

Assembly required

Minimal by design — no built-in subagents or plan mode. You (or your agents) compose the workflow via packages. Handle: fine if Pi is an engine your agents wire up; friction if you expect a finished experience.

Young & fast-moving

Created Aug 2025; daily commits; new-contributor PRs auto-closed. Powerful but a moving target. Handle: pin versions if you build on it; treat as "watch" until a concrete need (a Hermes rebuild) makes it load-bearing.

04 · Verdict

Verdict & a light try-it

1
Keep it as a "watch / SDK option," not your next daily tool.

Your daily local lanes (Claude Code, Codex, and Sculptor if you adopt it) are the better fit. Pi's value is latent — it matters the day you want to own an agent loop.

2
If curious, trial the CLI inside a sandbox.

On a throwaway repo copy, run Pi inside Docker with no real credentials, point it at an AGENTS.md, and feel the minimal loop. Do not run it bare on your Mac.

3
Bookmark it against a Hermes rebuild.

If you ever re-platform your Hermes ops bot, Pi's SDK (the thing OpenClaw builds on) is the natural, MIT foundation — that's when it moves from "watch" to "adopt."

Bottom line: Pi is an excellent, minimal, embeddable agent runtime — but it's a builder's foundation, not an operator's daily driver. For you it's a strong future SDK choice (especially for a custom agent like Hermes) and a "watch," gated on one hard rule: never run it without a sandbox, because it has no permission system of its own.
