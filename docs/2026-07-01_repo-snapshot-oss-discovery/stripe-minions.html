Deep dive · a reference to steal from, not install

Stripe "Minions"

Stripe's internal one-shot, end-to-end coding agents: an engineer messages in Slack, walks away, and comes back to a finished, test-passing PR ready for human review. At scale, 1,300+ PRs merged per week with zero human-written code against a ~30-million-line codebase. It's not a product you can install — it's a public writeup of an internal system built on a fork of Block's open-source Goose, and the value is the handful of transferable patterns it documents.

The one-paragraph fit for you

Minions is a north-star reference for your human-out-of-the-loop vision, and it maps unusually well onto pieces you already have: you run agents on Slack/Telegram via Hermes, you have a cloud lane (Cataclysm) for autonomous runs, and you're about to build a CI floor. Its three big ideas — Blueprints (deterministic + agentic nodes in one workflow), isolation-as-permissions (disposable, credential-less sandbox → run unattended, no prompts), and Slack-triggered one-shots → PR — are exactly the scaffolding your Fable 5 mission 5 (HOTL blueprint) is trying to design. You can't buy Minions; you can rebuild its shape at solo scale.

01 · Technical

How it works

Slack trigger→plan→implement→auto test + review→human review at PR only→merge

Stripe's Part 2 writeup discloses four components:

Blueprints the headline idea

A workflow expressed as a sequence of nodes where some nodes run deterministic code (git ops, linters, tests) and others run an agentic loop. Rigid, reliable steps alternate with creative steps in one pipeline — the LLM only does the middle.

Devboxes isolation = permission

AWS EC2-based sandboxes (the same env human engineers use), in a QA environment already isolated from production data and arbitrary network. Because the box is disposable and can't reach anything dangerous, agents run with full permissions and no confirmation prompts — "the blast radius is one disposable machine." Warm pool spins up in ~10s.

Toolshed MCP hub

A central internal MCP server hosting 400+ tools across internal systems and SaaS. MCP enforces permissions at the protocol level — agents can be cryptographically restricted from actions regardless of the prompt.

goose fork the engine

Minions runs on a heavily modified fork of Block's open-source Goose, on a track aimed at full autonomy — interleaving agent loops with deterministic code for git, linting, and testing.

Open source? Internal-only, with a public writeup. Goose underneath is open (Block/MIT); Stripe's fork, Blueprints, Toolshed, and Devbox provisioning are not released.

The single most portable idea

Isolation as the permission system. For an operator who won't read code, the safest way to run agents unattended isn't cleverer prompts or approval dialogs — it's a disposable sandbox with no production credentials and no network to anything dangerous, so a mistake's blast radius is one throwaway machine. That single principle is what lets Stripe run 1,300 unreviewed-code PRs/week safely, and it's the thing that makes "Randy doesn't review the code" tractable for you too. Pair it with Blueprints (deterministic scaffolding around agentic middles) and you have the backbone of your HOTL pipeline.

03 · Caveats

What to keep in mind

Not a tool — a pattern

You adopt the approach, not code. The engine (goose fork), Toolshed, and Devbox infra are internal. Handle: rebuild the shape with your stack — Claude Code + a container + Hermes + MCP.

Enterprise scale

EC2 warm pools and a 400-tool MCP hub are Stripe-scale. Handle: take the ideas at solo scale — one throwaway container, a handful of MCP tools, one Slack trigger.

Numbers are secondary-sourced

"1,300 PRs/week," "30M lines," "EC2/QA Devbox" come from the writeup and summaries, not something you can re-derive. Handle: treat as directionally true reference, not spec.

04 · Do this

Adopt this (feeds Fable mission 5)

1
Build a "blueprint-lite" around one agent task.

Deterministic nodes for git branch → lint → test (your CI floor) with an agentic node in the middle for the actual change. Start with one non-prod app.

2
Stand up one disposable, credential-less sandbox.

A container with no production S3/Pinecone/Webflow keys and restricted network, where an unattended agent can run with no prompts. This is the safety primitive for everything else.

3
Wire a Hermes → cloud-agent → PR trigger.

A Slack/Telegram message kicks a Claude Code cloud run that returns a review-ready PR — the Minions loop at your scale, and the concrete first slice of your voice-router.

Bottom line: Minions is the clearest existing proof that "trigger from chat → unattended agent → review-ready PR" works at scale, and its three ideas — deterministic+agentic Blueprints, isolation-as-permissions, and Slack-triggered one-shots — are directly buildable on your Hermes + cloud + CI stack. Study it as the blueprint for Fable mission 5; you rebuild the shape, not the code.
