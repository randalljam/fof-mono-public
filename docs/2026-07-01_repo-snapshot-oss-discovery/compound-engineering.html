Deep dive · methodology + plugin

Compound Engineering

Two things at once: a methodology from Every Inc. (Kieran Klaassen, Dan Shipper) whose thesis is that each unit of work should make the next one easier — every mistake, review, and insight is captured as durable context so productivity compounds — and a real, MIT-licensed Claude Code / Codex / Cursor plugin (everyinc/compound-engineering-plugin) that packages that loop as installable skills and commands.

The one-paragraph fit for you

This is the closest named articulation of what you're already doing. Your 878 markdown docs, your AGENTS.md rulebooks, your skills with append-only provenance, your PR-level review — those are compounding context. Compound engineering names the loop, gives it a discipline (plan → work → review → compound), and hands you a ready-made plugin that runs across both engines you use (Claude Code and Codex). The value for you isn't a new idea; it's a tested, packaged version of your own instinct — and a prompt to make the "capture the lesson" step deliberate rather than ad hoc.

✅ Why it resonates

  • Turns your doc/rule/skill habit into an explicit, repeatable loop.
  • "Every mistake becomes a rule or test" = durable memory, which you already value.
  • Cross-platform plugin: Claude Code, Codex, Cursor, and even Pi.
  • 80% plan/review, 20% execute — matches your operator-not-coder posture.

⚠️ What to weigh

  • The plugin's ~28 skills verify overlap your existing skills/ — don't double-run.
  • It's opinionated; Fable 5 prefers less-prescriptive prompts — adopt the loop, not every skill.
  • Productivity claims (300–700%) are promotional, not measured.
01 · Technical

How it works

The loop

brainstorm→plan→work→simplify→review→compound

You and the agent co-author a detailed plan; the agent implements it largely unsupervised and hands back a pull request; you review at the PR level; then the crucial step — compound — captures what worked and what failed into rules, skills, or tests so the next cycle starts smarter. The canonical short form is plan → work → review → compound; the plugin expands it as above.

The core principles

  • Each feature makes the next easier. Effort should invert from linear to compounding as the system accumulates durable context.
  • Tests and rules as memory. CLAUDE.md/AGENTS.md rules, skills, saved plans, and tests are the substrate that compounds — an agent's mistake becomes a note/rule so it never repeats it.
  • Invert the effort ratio to ~80% planning + review, ~20% execution; the human manages systems of agents rather than writing line-level code.
  • Parallel agents, with the engineer as orchestrator.

The plugin (the concrete artifact)

  • everyinc/compound-engineering-plugin — MIT, mostly TypeScript, very active (v3.x, 2026). Install via Claude Code's plugin system (e.g. /plugin install compound-engineering).
  • Cross-platform: Claude Code, Codex (app + CLI), Cursor, Copilot, Factory Droid, OpenCode, Pi, and more.
  • Ships skills (README says ~28 verify) exposed as slash commands: /ce-brainstorm, /ce-plan, /ce-work, /ce-code-review, /ce-compound, plus /ce-debug, /ce-ideate, and /lfg (autonomous full-loop run).

The real takeaway

Adopt the vocabulary and the loop more than the plugin. The single highest-value change is making "compound" a deliberate final step of every mission — the agent, before finishing, writes back what it learned as a rule/skill/test. That's a two-line addition to your fable5-operating-contract.md (you already have a memory-notes clause — promote it to a required step). The plugin is worth installing to study how Every encodes the loop as skills, then port the ideas into your own skills/ rather than running a second, overlapping skills system.

03 · Honest

Frictions

Skill-system overlap

Its ~28 skills overlap your skills/ and the Superpowers skills you're also evaluating. Running three skill systems at once creates confusion and cost. Handle: pick your canonical skills home (yours), and treat the plugin + Superpowers as sources to harvest from.

Prescriptiveness vs. Fable 5

Compound engineering is an opinionated, step-heavy method. Fable 5's guidance warns that over-prescriptive prompts reduce its output quality. Handle: use the loop as scaffolding on Opus/Claude Code; give Fable the goal and constraints, not the full ceremony.

Promotional claims

The big productivity numbers come from third-party posts, not measured Every data; skill counts vary by version. Handle: treat the method as sound and the numbers as marketing; measure your own before/after.

04 · Do this

How to adopt (low effort, high leverage)

1
Make "compound" a required final step.

Add one line to fable5-operating-contract.md §6/§7: before ending a mission, write the lesson learned back as a rule, skill, or test. This alone captures most of the value with zero new tooling.

2
Install the plugin on a non-prod app to study it.

In a Claude Code session on math-quiz, install the plugin and run one /ce-plan → /ce-work → /ce-compound cycle. Read what the "compound" step produces — that's the artifact to mirror in your own skills.

3
Harvest, don't adopt wholesale.

Port the 2–3 most useful skills into your skills/ with your provenance headers; keep one canonical skills system. Decide compound-engineering vs. Superpowers vs. your own as the source of the planning gate — don't run all three.

Bottom line: compound engineering is the name and the loop for the system you've been building by instinct. Adopt the loop (especially the deliberate "compound" step) into your contract, study the plugin, and harvest a few skills — but keep one canonical skills home rather than stacking overlapping frameworks.
