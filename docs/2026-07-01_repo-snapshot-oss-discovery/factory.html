Deep dive · commercial autonomous platform

Factory.ai — "Droids"

A commercial "agent-native development" platform whose agents, Droids, run full-SDLC tasks — feature work, refactors, review, incident response — across a terminal CLI, a headless one-shot mode, IDE, web, desktop, and Slack, with state synced across all of them ("start in your terminal, finish on your phone"). It's model-agnostic with bring-your-own-key, does per-task model routing, and topped Terminal-Bench (58.75%). It's a paid product ($20/$100/$200 tiers), enterprise-leaning.

The one-paragraph fit for you

Factory is essentially a commercial, productized version of the multi-model, multi-surface operation you already run by hand (Claude Code cloud + Codex local + phone). Its strengths line up with your instincts: model-agnostic routing, a phone-to-terminal continuum, ticket→PR. But you're happy and cheap on Claude Code, and Factory is a paid platform that would replace your center of gravity rather than fill a gap. The highest-value read for you is not "adopt it" but "steal its best patterns" — headless one-shot agents in CI, tiered autonomy, and persistent per-project agent machines — into your existing flow.

✅ Patterns worth stealing

  • Droid Exec — headless one-shot (droid exec) for CI/CD, read-only by default.
  • Tiered autonomy — read-only → --auto gated by risk tier.
  • Droid Computers — persistent, stateful per-project machines (even your own Mac Mini/VPS).
  • BYOK + mid-session /model switching.

⚠️ Why "watch," not "adopt"

  • Paid, commercial; enterprise focus vs. your OSS-leaning posture.
  • Would add a 4th surface and re-center you off Claude Code.
  • "Fully tested" only on Anthropic/OpenAI official APIs.
  • CLI sandbox is agent-enforced, not OS-level — needs a container.
01 · Technical

How it works

Surfaces

  • CLI / terminal (droid) — the flagship agent surface.
  • Droid Exec (droid exec) — headless one-shot for CI/CD, shell scripts, batch; read-only by default, --auto enables edits/commands under risk-tiered gating.
  • Factory Bridge — connects a cloud/web Droid to your local machine and local repo, so the agent runs against your local dev env without provisioning a remote one.
  • Plus desktop, IDE, web, and Slack — state synced across all.

Execution & models

  • Model routing / BYOK: multi-provider; plug in your own Anthropic/OpenAI keys, OSS providers, or local models; switch mid-session with /model. Only Anthropic + OpenAI official APIs are "fully tested."
  • Execution environments: (1) local via Factory Bridge; (2) Droid Computers — persistent remote machines (Factory cloud, or register your own VPS / Mac Mini / on-prem) that retain packages, files, and services between sessions; (3) ephemeral cloud sandboxes on higher tiers.
  • Pipeline: Linear/Jira ticket → Droid reads context → branch → code → PR referencing the ticket → ticket status update. MCP supported. Positions "thousands of Droids in parallel" for migrations.

Status

$50M Series B (Sept 2025, NEA + Sequoia/NVIDIA/J.P. Morgan). Pricing: no free tier — Pro $20 / Plus $100 / K2 $200 per month, token-based; Teams/Enterprise custom (SSO, ZDR, on-prem). GA self-serve with a heavy enterprise push (EY, NVIDIA, MongoDB, Zapier cited).

The honest placement

Factory is a strong product, but for you it's a strategic alternative to evaluate, not a gap-filler — adopting it means re-centering your whole operation onto a paid platform when Claude Code already serves you well and cheaply. The durable value is the ideas: put a headless one-shot agent in a GitHub Action (your CI-floor mission), adopt read-only-by-default → risk-gated autonomy for unattended runs, and consider registering a spare Mac/VPS as a persistent per-project agent box. You can implement all three on your current stack without paying for Factory.

03 · Cautions

What to weigh

Commercial re-centering

Adopting Factory means moving your center of gravity to a paid, enterprise-focused platform. Handle: only worth it if you outgrow Claude Code's ergonomics or need its team/enterprise features — otherwise steal patterns, stay put.

Another surface

You already juggle Cursor, Claude Code, Codex. Factory adds a fourth world your agents and EA must learn. Handle: consolidation is your stated goal — don't add a surface without retiring one.

Sandbox is agent-enforced

The CLI's "project directory only" limit is enforced by the agent, not the OS. Handle: for higher autonomy, run it in a container/VM regardless (same rule you'd apply to any agent).

04 · Verdict

Verdict

1
Steal three patterns into your current stack.

(a) A headless one-shot agent in a GitHub Action; (b) read-only-by-default → risk-gated autonomy for unattended runs; (c) a persistent per-project agent machine. All doable on Claude Code/Codex today.

2
Only trial Factory itself if you feel a real limit.

If Claude Code's ergonomics or team features start to pinch, run a Pro-tier trial on a non-prod app and test droid exec in CI. Otherwise it's a "watch."

Bottom line: Factory is a polished, benchmark-leading commercial version of the multi-model, multi-surface operation you already run — but you're well-served and low-cost on Claude Code, so the win is copying its patterns (headless CI one-shots, tiered autonomy, persistent per-project machines) rather than re-platforming onto a paid tool.
