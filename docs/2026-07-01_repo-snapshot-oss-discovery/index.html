04 · Under the hood

Two spotlights you asked for

Minecraft mod · the Forge port

A genuinely sophisticated build problem, solved cleanly. build-and-deploy.py is a Python dispatcher that orchestrates multi-loader cross-compilation:

  • JDK routing — MC 1.20.x→Java 17 (ForgeGradle 6 rejects 21+), 1.21.x→Java 21, 26.x→Java 25.
  • Gradle routing — Loom 1.15+ needs Gradle 9; ForgeGradle 6 needs Gradle 8 → nested loader roots (fabric/ + forge/, each its own wrapper).
  • Shared common/ platform-abstraction layer; loader-specific impls for networking, inventory, screens.
  • Companion targets — a Forge build auto-rebuilds Fabric to keep mod_version in sync; per-target Prism instance deploy paths.
  • 15 milestone plans (M1→M6) in .cursor/plans/, a parity matrix, and a playtest log — planned before code.

prism-sync · this-morning's web app

A real, tested full-stack tool built in a plan-first loop:

  • Stack — FastAPI + uvicorn shelling to ssh/rsync; vanilla HTML/CSS/JS matrix UI; TOML config; port 8770.
  • Does — computers×instances reachability matrix, dry-run sync preview, one-click push/pull, mod-jar-aware sync (detects superseded jars).
  • Tests — 5 modules (~410 lines), ssh/rsync fully mocked → no live Macs needed.
  • Workflow tells — a locked .cursor/plans/ plan with 10 completed todos, a living SPEC.md (M1 done, M2/M3 sketched), scoped conventional commits, docs paired with every feature.

Both spotlights share the same fingerprint: plan written before code, milestones with explicit parity/verification, tests that mock external systems, and docs kept in lockstep. That discipline, applied by a non-professional coder to a Minecraft Forge port and a FastAPI app in the same week, is the thing to preserve as you add autonomy.

05 · The substrate

The agent-first workflow

This is the part your influencers mostly aren't doing. It's not a model or a prompt — it's an operating system for directing agents safely, encoded as scripts, hooks, skills, and rulebooks.

Multi-harness orchestration

Cursor local

Primary heavy-work surface. Full CLI, flyctl, pytest, interactive input. Rules in .cursor/rules/ (commit format, guardrails) auto-applied.

Claude Code cloud

Deep-context review, multi-file autonomous changes, /land command. No local exec — the "review & big-refactor" agent.

Codex worktrees

.codex/environments/ lightweight venv setup; local worktrees for build/test-heavy work (esp. Minecraft/Gradle).

Hermes remote bot

Autonomous Telegram/chat agent on Fly (s6-supervised), with its own skills, cron jobs, config back-propagation, and S3-secured backups. Runs family/ops automation independently.

Skills — one source of truth, many wrappers

The model

Procedures + scripts live once in skills/<category>/<name>/; each platform (Hermes SKILL.md, CC commands, Cursor) wraps them. Every skill README carries provenance (source URLs) and an append-only history log — who/when/which platform/which thread.

What exists

repo-ops/ is the richest: clone-bootstrap, promote-to-main, merge-main-to-branches, repo-size-audit, repo-status-report, local-files-snapshot-backup, hermes-branch-testing. Plus education/, family/, media/ skills.

Worktrees & the _LOCAL_FILES mount

One branch per Cursor window, each a git worktree; worktree_bootstrap.sh symlinks a shared .venv/.env, merges VS Code settings, installs hooks, and publishes the branch so cloud agents can pick it up. Durable local-only data (corpora, DBs) lives once under _LOCAL_FILES/fof-mono/ and is symlinked into every worktree — local_files_check.py audits/repairs the mounts before a worktree is deleted. A custom Cursor extension even grays the symlinked paths in Explorer.

Guardrails that make autonomy safe

Pre-commit hook

Blocks binaries, media, archives, DBs, ML blobs, and any new file >512 KB (small runtime assets allowlisted). Keeps agent commits clean.

Branch discipline

Never push the harness auto-branch; verify ancestry with merge-base; a tracked ledger in plans/git/branch-map.md. Descriptive prefixes (feature/fix/refactor/import…).

Data out of repo

S3 [S3-FILES-BUCKET] + [S3-BUCKET] (PII), keyed 1:1 to repo paths, only manifests committed. core/s3_archive.py build/upload/verify/refresh.

Convergence planning

Local + cloud agent iterate the same plan docs in numbered rounds; "green light = zero remaining edits"; do the work, don't describe it.

Scoped commits

<type>(<app>): imperative so main stays readable after non-squash merges; one logical change per commit.

Pre-PR testing

Mandatory: write + run tests, describe coverage, note in PR body. The test floor before broader autonomy.

Where this sits on the maturity curve

Ahead of the pack: worktree-parallel agents, one-source skills with provenance, cloud/local handoff discipline, data-out-of-repo hygiene, convergence planning, a remote autonomous ops agent (Hermes). Genuine gaps (your own roadmap): no CI gates yet, no automated/AI PR review in the loop, no preview-deploy gates, no LLM-graded acceptance tests or local "fakes" for self-verification, and code-intelligence/graph tooling still unstandardized. Section 06 is chosen to close exactly those gaps.
