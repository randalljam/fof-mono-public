Deep dive · OSS discovery top pick #1

Sculptor by Imbue

A free, open-source (MIT) desktop app that manages many coding agents running in parallel, each in its own isolated copy of your repo — and it runs both Claude Code and Codex, the two engines you already use locally. Its signature "Pairing Mode" syncs any agent's working tree and git state straight into your Cursor window so you can test and hand-edit its work. In other words: it's a polished UI for the exact hand-rolled "one worktree per branch, one agent per window" workflow you built in your worktrees guide.

The one-paragraph fit for your setup

Sculptor is a local-Mac tool for your two local lanes (Cursor worktrees + Codex local worktrees). It consolidates them under one UI, adds real per-agent isolation (containers instead of a shared .venv), and bridges the gap you handle manually today — getting an agent's isolated work back into your IDE — via Pairing Mode. It does not touch your Cataclysm cloud lane or your iPhone flow: those stay on Claude Code's cloud. So think of Sculptor as "upgrade the local-parallel-agent lane," not "replace how I work everywhere."

✅ What it's great at for you

  • Running 3–5 local agents at once across your projects, each isolated, in one window.
  • Mixing Claude Code and Codex per task without separate terminals/worktrees.
  • Pairing Mode → an agent's branch appears live in Cursor to test/edit.
  • Integrated GitHub PR flow (via gh) matching your PR-level review.

⚠️ What to know going in

  • Local & Mac-only (Apple Silicon); needs Docker running + the Claude CLI.
  • Introduces a third worktree location; your _LOCAL_FILES/bootstrap don't carry over as-is.
  • Auto-names branches <user>/<slug> — needs config to match your branch discipline.
  • Experimental research preview — expect bugs and change.
01 · Technical

How it works under the hood

Sculptor is an orchestrator, not a model. The frontend is a React/TypeScript desktop app; the backend is Python. It shells out to real agent CLIs and wraps them in isolation, review, and git plumbing.

Isolation — how parallel agents don't collide

Each unit of work is a workspace = one branch + one isolated working copy. Sculptor documents three workspace modes: worktree (a branched dir sharing your git history, at ~/.sculptor/workspaces/[ID]/code/), clone (a fully independent copy with mirrored remotes), and in-place (edits your real repo — no isolation). Separately, an experimental container backend can run each agent inside a Docker container built from your dev-container spec, so it can install deps, run tests, and execute code without touching your machine.

Important nuance — containers vs. worktrees verify

Imbue's announcement/blog describe a Docker container per agent as the whole point ("keeps your machine safe," deps baked into a cached image, "minutes → seconds"). The open-source repo docs say the default is a host git worktree, with the container path marked experimental. These probably reflect different generations/configs of the app. Practically: expect Docker to be involved, but confirm the current default on install — it changes the story on how it meshes with your existing worktrees.

The agent engine — Claude Code & Codex, your keys

  • Sculptor runs Claude Code (the Claude CLI is a setup prerequisite) and supports Codex (ships a Codex output schema + terminal-agent docs). You pick model, "fast mode," and effort in Settings.
  • Bring your own credentials: your existing Claude Pro/K2 subscription (OAuth via the Claude CLI) or an Anthropic API key — same for OpenAI/Codex. Sculptor adds no model cost; you pay your own usage.
  • It syncs your Claude Code config into every agent docs-snippet — slash commands, subagents, and MCP servers — and reads repo-level .claude/ plus user ~/.claude/skills and ~/.claude/commands. You can add custom MCP servers too.

Pairing Mode — the headline feature

One toggle brings a chosen agent's work into your local repo + IDE, keeping files and git state synced both ways in real time, so you run/test/edit from your normal environment. The reported mechanism is Mutagen high-confidence — a bidirectional, filesystem-watching sync with three-way merge (not a git pull, not a bind mount). The agent sees your edits live; Sculptor flags likely merge conflicts and can hand them back to the agent; your local repo stays untouched until you deliberately Pull. Known limit: sync lag on repos with >10,000 files.

Git & PR model

workspace = branch <user>/<slug>→ commit on branch→ Create PR (uses gh)→ PR vs. target branch, status tracked in-app

Multiple agents can share one workspace (same working copy — so they can conflict); real parallelism-without-conflict comes from separate workspaces. Extra git skills: /stack (dependent workspaces stacked on the current branch) and /handoff (move work to a fresh agent).

Extras worth knowing

"Suggestions" review agent

An always-on (toggleable) reviewer that scans agent changes for fake "tests passed," CLAUDE.md violations, abstraction breaks, etc., and can fix them in parallel. Custom LLM checks supported. This is the "grounded" in the repo's "grounded, parallel coding agents."

Repo & env config

/setup-repo writes .sculptor/code.md (structure, branch naming, build/run/pre-commit), testing.md, docs.md. Secrets via global + per-repo .sculptor/.env. Setup commands run at workspace creation; dev-container spec pre-bakes the image in container mode.

Status & license

MIT, open source, free in beta (pay only your LLM usage). "Experimental research preview," actively maintained (public changelog). macOS Apple Silicon + Linux; Windows via WSL. Privacy tiers: Essential / Standard / Full-contribution.

04 · Honest

Frictions with your specific setup — and how to handle them

A third worktree location

You already have Documents/Code/ worktrees and ~/.codex/worktrees/. Sculptor adds ~/.sculptor/workspaces/. Handle: decide Sculptor is the home for a class of work (e.g. all local parallel agent runs) rather than mixing it with hand-made Cursor worktrees on the same branches — one branch shouldn't live in two managers at once.

_LOCAL_FILES & bootstrap don't carry over

Your shared-venv symlinks and worktree_bootstrap.sh are Cursor-worktree-specific. Sculptor workspaces get their environment from setup commands + dev-container spec + .sculptor/.env instead. Handle: re-express the essentials (venv install, env vars, local-file mounts) as Sculptor setup config once via /setup-repo. Container isolation is arguably better than the shared venv anyway.

Branch naming vs. your discipline

Sculptor auto-names branches <user>/<slug> and can auto-open PRs. Your AGENTS.md mandates descriptive feature/… names, one working branch per session, and an ancestry ledger. Handle: set branch-naming + target-branch rules in .sculptor/code.md, and keep "open the PR" a deliberate step (as you do now) rather than fully automatic.

Docker + Mac-only + beta

Needs Docker running, Apple Silicon, and it's an experimental preview. Handle: treat it as an evaluation on non-production work first (e.g. math-quiz, a kids' app), not on the qrag production path. Keep Cataclysm as your reliable primary lane while you trial it.

Big-repo sync lag

Pairing Mode reportedly lags on repos with >10k files. fof-mono is ~1,600 tracked files, so you're well under — but if node_modules or data dirs leak into a workspace, sync could bog down. Handle: your existing .gitignore/data-out-of-repo hygiene already helps here.

Two review systems

Sculptor's "Suggestions" overlaps with the CI/AI-review floor you're planning (Fable 5 mission 2, CodeRabbit/PR-Agent). Handle: let Suggestions be the fast in-loop check on the Mac; keep the CI gate as the merge gate. They're complementary, not redundant.

05 · Do this

A concrete, low-risk try-it plan

1
Install & first run.

On the Mac: ensure Docker is running and the Claude CLI is installed/logged in, download Sculptor (Apple Silicon), run the wizard, point it at a clone of fof-mono. Run gh auth login if you want in-app PRs.

2
Confirm the isolation model.

Check whether your version defaults to worktrees or Docker containers (the nuance flagged above), so you know how it relates to your existing worktrees. Run /setup-repo to capture build/run commands and branch naming in .sculptor/.

3
Run two agents in parallel on safe work.

Spin up two workspaces on non-production tasks — say a Claude Code agent on a math-quiz doc/test and a Codex agent on a Minecraft/Gradle build task. This directly tests the "both engines, isolated, at once" value on your real projects.

4
Exercise Pairing Mode into Cursor.

Pick the more promising agent, toggle Pairing, and confirm its branch shows up live in your Cursor window — edit a file locally and watch the agent see it. This is the make-or-break feature for your workflow.

5
Decide the boundary.

If it earns its place: use Sculptor as your local parallel-agent manager (Claude Code + Codex on the Mac), keep Cataclysm for cloud/phone autonomous runs, and keep hand-made Cursor worktrees only for the branches you're personally editing. Write the boundary into ai-coding-system-dev.md so it's a decision, not a drift.

Bottom line: Sculptor is the closest off-the-shelf match to the local multi-agent workflow you've been building by hand — and it's the only one that natively runs both Claude Code and Codex with real isolation and a live path back into Cursor. It won't change your cloud/phone habit, and it adds a Docker dependency and a beta's rough edges. Trial it on the Mac for local parallel work; keep Cataclysm as your dependable primary lane.
