## Explantion of .venv size
Yes — `.venv` is your **local Python virtual environment**: a private copy of the interpreter plus every package this repo needs to run tests, Chalice apps, transcription, LLM code, etc. It is **not tracked by git** (`.gitignore` has `.venv/`), and you’re right that it was **recreated fresh** in fof-mono via `python -m venv .venv` + `pip install -e .` — not copied from corpus-tools. Only tiny `.vscode/` settings came over.

## Why it’s ~2.4 GB

Almost all of it lives in `.venv/lib/python3.12/site-packages/` — **449 installed packages** pulled in by `dependencies/requirements_2026-06-02.txt` through `setup.py`. The biggest offenders on disk:

| Package | Size | What it is |
|---|---|---|
| `torch` | 571 MB | PyTorch (speaker ID / ML) |
| `kaleido` | 248 MB | Bundled headless browser for Plotly static chart export |
| `plotly` | 175 MB | Charting / QA visualizations |
| `cv2` | 154 MB | OpenCV |
| `numpy` + `scipy` | ~210 MB | Scientific stack |
| `googleapiclient` | 97 MB | Google Drive API (transcribe) |
| `onnxruntime` | 74 MB | ML inference runtime |
| `awscli` + `botocore` | ~51 MB | AWS CLI + every AWS service model |

That requirements file is a **kitchen-sink install** from years of corpus-tools work: LangChain, LlamaIndex, SpeechBrain, spaCy, PyTorch, Plotly, AWS CLI, Deepgram, etc. The venv is big because the dependency list is big — not because anything went wrong during cutover.

For comparison, corpus-tools’ `.venv` is actually **larger**: ~3.6 GB and ~127,500 files vs fof-mono’s ~2.5 GB and ~110,100 files. So fof-mono’s venv did shrink some, but not by 10×.

## Why ~110,000 files (not just “Python”)

A venv isn’t one program — it’s **hundreds of packages**, each shipping many small files. File count and disk size don’t scale together.

Top packages by **file count**:

| Package | Files |
|---|---|
| `plotly` | ~30,500 |
| `torch` | ~12,100 |
| `awscli` | ~6,200 |
| `jedi` | ~5,700 |
| `sympy`, `pandas`, `langchain*`, `scipy`… | thousands each |

Roughly **39,000 `.py` files** and **~44,000 `__pycache__` entries** alone in site-packages. Modern Python packaging tends toward many small modules, and heavy packages (Plotly, AWS service JSON models, PyTorch, LangChain) explode the count even when total MB is modest.

## The “10× shrink” you noticed

That’s the **whole repo working tree**, not `.venv`:

- **corpus-tools**: ~24,582 MB (mostly `data/`, `logs/`, `_archive/`, fat `apps/` worktrees)
- **fof-mono**: ~2,459 MB — and **~2,238 MB of that is still `.venv`**

So the cutover worked: bulk data and artifacts are gone from the tree. What’s left locally is mostly “machine to run this codebase” — and right now that machine is a very fully-loaded Python env.

## Practical takeaway

`.venv` is **local-only, regenerable, and expected**. You can delete and recreate anytime:

```bash
rm -rf .venv
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

If you want it smaller long-term, the lever isn’t the venv itself — it’s **splitting or trimming requirements** (e.g. optional extras for torch/speechbrain/plotly/kaleido only when you need those features). Happy to map which packages are actually required vs legacy if you want to tackle that next.
